# DICE TACTICS 基本形

ダイス × ターン制の戦術ボードゲーム。このフォルダは、検証用プロトタイプ（Prototype 01〜03）から切り出した **基本形** で、UI の改善を進めるための出発点。

- 盤面: 10×10、各陣営 6 体（リーダー・戦士×2・弓使い×2・魔法使い）
- AP: **被害連動ダイス**（基本 1 ＋ ダイス 3 個。リーダー以外の味方を失うほどダイスが強化され、1〜7AP → 最大 1〜10AP）
- 対戦相手: CPU（標準）
- ルールの詳細: [RULES.md](RULES.md)

## 起動

必要なもの: Node.js 18 以上。外部パッケージは不要（`npm install` も不要）。

- **Windows**: `launch.bat` をダブルクリック。黒いウィンドウでサーバーが起動し、既定のブラウザでゲームが開く。終了するときはそのウィンドウを閉じる。ポート 8130 が使用中なら次の空いているポートを使う。
- **その他**: `npm start`（または `node serve.js`）で起動し、表示されたアドレス（既定 http://localhost:8130/）を開く。

ES Modules と Web Worker を使うため、`index.html` を直接開く（file://）と動かない。必ずサーバー経由で開く。

## 遊び方

スマートフォンの縦画面を主に想定した 1 画面のレイアウト（PC では中央に配置）。上から「両陣営の状態」「盤面」「情報行」「ダイスと AP・ターン操作」「補助メニュー」の順に並ぶ。

1. 「ダイスを振る」（Space）で、このターンの AP が決まる。主ボタンは、振った後に「ターン終了」へ切り替わる。
2. 自分の駒をタップして選ぶ。青いマス = 移動先（数字は消費 AP）、赤い鉤形の敵 = 攻撃できる相手。
3. 移動先や敵をタップすると **プレビュー**（経路・消費 AP・移動後に狙える敵と「移動 3＋攻撃 2＝計 5AP」・AP 不足の敵は灰色の鉤形・ダメージ・弓の押し出し先や押し出せない理由・岩越しの魔法）が出る。**同じ場所をもう一度タップ**（または「確定」・Enter）で実行する。攻撃するまでの移動は「戻す」（Z）で取り消せる。
   - 敵の駒をタップすると、その敵が次のターンに最大 AP を出した場合に **攻撃前に動けるマス（橙の点）** と、**味方を狙うのに必要な最小 AP**（味方の駒の左下の数字）が出る。可能性の表示で、確定した攻撃ではない。
   - CPU が直前のターンに動かした経路は、あなたがダイスを振るまで橙の点線で残る。CPU の手番では「CPU の狙い」（これから行う攻撃の対象）を短く表示する。
4. 「ターン終了」（E）。AP と動ける駒が残っているときは、もう一度押して確定する（誤タップ防止）。CPU が 1 手ずつ行動する。
5. 味方を失うとダイスが強化され、盤面に「ダイス強化 ▲0 → ▲1（最大 7 → 8AP）」のように表示される。両陣営の強化段階・最大 AP・残りの駒は画面上部に常に出ている。

補助メニュー: 履歴（行動履歴）・敵の射程（CPU が平均的な AP で狙える味方に赤い斜線、王を狙える最小 AP）・ルール・設定（先手・CPU の再生速度・移動を 1 タップで確定・演出を控えめに・新しいゲーム）。結果画面には両陣営の統計（平均・最大 AP、使った AP、攻撃・撃破・押し出しの回数）が出る。

キー: Space = ダイスを振る、Enter = 確定（振る前はダイスを振る）、E = ターン終了、Z = 移動を戻す、1〜6 = 自軍の駒を選択（王・戦1・戦2・弓1・弓2・魔）、Esc = 取り消し・シートを閉じる。

## 構成

```
index.html              画面の骨組み
styles.css              見た目
launch.bat / serve.js   起動（依存なしの静的ファイルサーバー）
src/core/               ゲームの中身（UI に依存しない。Node.js でもブラウザでも動く）
  config.js             盤面・ユニット・ルールの定数、初期配置
  dice.js               被害連動ダイス（段階・正確な確率分布・ダイスを振る）
  rules.js              ルールエンジン（合法判定・移動・攻撃・押し出し・勝敗・ターン）
  ai.js                 CPU（標準）
  rng.js                シード付き乱数
src/ui/                 画面
  app.js                ゲームの進行と入力（ダイス → プレビュー → 確定 → ターン終了 → CPU の手番）
  view.js               描画（game の状態から DOM を作るだけ）
  fx.js                 演出（applyAction の events を再生するだけ。状態は計算し直さない）
  art.js                図案（駒・紋章・ダイスの目・ロゼットの SVG。外部の画像は使わない）
  audio/                音（すべて Web Audio で合成。音声ファイルは使わない）
    engine.js           AudioContext・音量のバス・残響・ダッキング・音の設定
    instruments.js      楽器の合成（竪琴・低音の撥弦 = Karplus-Strong、弦楽・笛・枠太鼓）
    score.js            BGM の楽譜（メインの 1 曲と、主題を引用したジングル）
    render.js           楽譜の書き出し（BGM は 1 ループを書き出して継ぎ目なく繰り返す）
    music.js            BGM の再生
    sfx.js              効果音（演出と同じ events・操作から鳴らす）
  cpu.js                CPU の呼び出し（Web Worker。使えなければメインスレッド）
  cpu-worker.js         CPU 思考用の Web Worker
tests/                  自動テスト（npm test）
```

### UI を作り直すときに使うコアの API

UI から使うのは主に次の関数。状態はイミュータブルで、各関数は新しい状態を返す。

| 関数 | 用途 |
|---|---|
| `makeConfig()`（config.js） | 盤面・ユニット構成の設定 `cfg` |
| `createGame(cfg, { firstSide })` | 新しいゲーム（`phase: 'roll'`） |
| `rollDiceFor(state, rng)` → `beginTurn(state, dice)` | ダイスを振ってターン開始（`phase: 'act'`、`state.ap` が決まる） |
| `moveOptions(state, unit)` | 移動先の一覧 `[{cell, cost, path}]` |
| `attackOptions(state, unit)` | 攻撃できる敵の一覧 `[{target, dir, overObstacle, cost, hit}]`（`hit` = 撃破・押し出し先の予測） |
| `validateAction(state, action)` | 行動が違法なら理由の文字列（合法なら null） |
| `applyAction(state, action)` | 行動を適用。`{ state, events }` を返す。events（move の経路・attack・damage・kill・knockback など）を演出に使える |
| `endTurn(state)` | ターン終了（相手の `phase: 'roll'` へ。40 ラウンドで引き分け） |
| `diceMaxOf(state, side)` / `diceStageOf(state, side)` | 各陣営のダイスの最大値・強化段階 |
| `planTurn(state)`（ai.js、UI からは cpu.js の `requestPlan`） | CPU の行動列 `{ actions, info }`。actions を順に `applyAction` すればよい |

行動は `{ type: 'move', unit, to }`・`{ type: 'attack', unit, target }`。ユニット番号は 0〜5 が人間族（王・戦1・戦2・弓1・弓2・魔）、6〜11 がモンスター族。マス番号は `y * 10 + x`（y = 0 が上端）。

デバッグ用に、ブラウザのコンソールから `window.__dt`（ゲームの状態と操作関数）を参照できる。

## 切り出し元との関係

- 切り出し元: DICE TACTICS Prototype 01〜03（Classic 7×7・Expanded 10×10、旧ダイス・固定 AP、CPU 3 種、シミュレーション・分析ツール）。この基本形には、そのうち「Expanded・被害連動ダイス・CPU 標準」だけを残した。
- ルールと CPU は切り出し元と同じ。切り出し元の `tools/basic-equivalence.js` で、同じシードの対局を両方の実装で並べて動かし、出目・CPU の行動・局面が 20 試合（817 ターン）すべて一致することを確認した。
- UI は作り直した。その後、「古代モザイク × チェスの駒」の方向で再設計した（ウル王のゲームの象嵌を着想にした盤面、立体感のある抽象駒、スマートフォン縦画面のレイアウト、タップのプレビューと確定、events に基づく短い演出）。CPU の狙いの表示は含めていない。

## 画面の設計

- **盤面**: 貝・象牙色のマスをラピスラズリの藍の目地で区切り、目地の交点に金の点を打った象嵌。外枠は金の縁・鋸歯文の帯・藍の座標帯。四隅のロゼットは飾りで、ゲーム上の効果はない。岩は格子を彫った黒い瀝青の石板で、駒とも通常のマスとも形と明るさで区別する。
- **駒**: 人間族 = ラピスの円い台座＋玉縁、モンスター族 = 紅玉髄の八角形の台座＋鋸歯縁（色に頼らず形でも区別）。台座の上に紋章を浮き彫りにする（王 = 王冠、戦士 = 剣、弓使い = 弓と矢、魔法使い = 八芒星）。リーダーは金の二重縁。駒の下に HP の目盛り（最大 4）、右上に同じ職業の番号、左上に状態の印（! 今攻撃できる / ➜ 移動済み / ✓ 行動済み）。
- **状態の色**: 選択 = 金の二重枠、移動先 = 青、攻撃対象 = 赤の鉤形、CPU が動かしている駒 = 橙の枠。どれも色だけでなく枠の形・記号・明るさで区別する。
- **演出**: 移動は経路に沿って滑らせ、近接は踏み込みと斬撃、弓は矢、魔法は光球（岩越しは弧）。押し出しは 1 マス滑らせ、押し出せないときは ✕ と理由を出す。撃破は駒が光って消える。演出は `applyAction()` の events を順に再生するだけで、時間待ちにはすべて上限を付けている（背景タブでも止まらない）。演出の中で例外が起きても打ち切って進行を続ける。OS の「視差効果を減らす」や設定の「演出を控えめに」では動きを省く。
- **CPU の狙い**: `requestPlan()` の `info` には狙いの情報がないため、これから再生する行動列の攻撃対象から作る（予言ではなく、直後の行動の要約）。

## 音

- **効果音**（初期設定: オン）: ダイス（振る・止まる・強化されたダイスの最大の目）、駒の選択・プレビュー・無効な操作・移動を戻す・ターン終了の確認、移動・剣・弓・魔法・命中・押し出し・押し出し不可・撃破、手番の開始、AP が多いとき。CPU（モンスター族）側は少し低く暗い音にして、音だけでもどちらの行動か分かるようにした。
- **BGM**（初期設定: オフ。設定の「BGM」でオン）: 「古代王宮の戦略音楽」。竪琴を主役に、枠太鼓・低音弦・控えめな笛。A（静かな導入）→ B（リズムと旋律の展開）→ A'（主題に戻る変奏）の約 100 秒の曲を、継ぎ目なくループする。手番では切り替えない。効果音が鳴る間は BGM を少し下げる。
- **ジングル**: 被害連動ダイスの強化（主題を引用した上昇フレーズを BGM の拍に合わせて重ねる。CPU 側は暗い変形）、勝利・敗北・引き分け（BGM を止めてから鳴らす）。効果音か BGM のどちらかがオンなら鳴る。
- ブラウザの自動再生の制限のため、音は最初に画面をタップ（またはキーを押す）したあとに鳴る。iOS の通話・画面ロックなどで音が止まった場合も、次のタップで再開する。
- iPhone では Web Audio の音が着信音と同じ扱いで、消音モードだと鳴らない。そのため最初のタップで「メディアの再生」に切り替える（iOS 17 以降は `navigator.audioSession`、それより前は無音の音声を再生し続ける）。メディア扱いになるので、ほかのアプリで再生中の音楽は止まることがある。補助メニューの「消音」ですべての音を消せる。背景タブ・消音中・効果音も BGM もオフのときは、音の処理を止める。
- BGM は初めてオンにしたとき、1 ループ分の書き出しに 1〜数秒かかる（区間に分けて同時に書き出し、その間も操作は止めない）。その後はループ再生するだけ。OfflineAudioContext に対応していない古いブラウザでは BGM をオンにできない（効果音は鳴る）。
- CPU の設計・シミュレーション結果・未確認事項は、切り出し元の CPU_DESIGN.md・DICE_EVOLUTION_REPORT.md を参照。
